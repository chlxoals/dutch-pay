### 결정과 이유
- 웹 선택: 정산은 식당에서 휴대폰으로 하는 일이 많고, 발표 때 링크만으로 접속할 수 있으며, exe는 빌드와 보안 경고 부담이 있어서
- 더치페이 유지: 이미 배포까지 마쳤고, 주제를 바꿔도 점수상 이득이 없어서. 대신 범위를 키움
- 영수증 AI 인식, 자연어 입력 제외: 수업 규칙의 "실행 중 AI API 호출 금지" 때문
- 실시간 공유방 삭제: 카톡으로 충분히 대체되어 실용성이 약하고 서버 설정 위험이 커서
- 환율은 지출마다 개별 저장, 직접 입력이 기본: 여행 중 환율이 바뀌고 현금/카드 환율이 다르기 때문
- 서비스를 다통화 정산으로 키운 이유: 교수님이 "AI를 쓰면 8시간에 더 큰 것을 만든다"는 기준을 말씀하셨고, 처음 버전은 2시간 미만 분량이라 작았기 때문

### 겪은 문제 (회고용)
- 이전 세션에서 파일 카드 표시 오류가 반복되어 대화가 끊김. 한글이 들어간 사용자 경로가 원인일 가능성. 해결: 새 대화에서 폴더를 다시 연결하고 HANDOFF.md에 기록
- 컴퓨터를 껐다 켜서 GitHub 저장소가 어디 있는지 헷갈림. 해결: 주소창에 github.com/chlxoals/dutch-pay 직접 입력
- GitHub 업로드 메뉴 위치를 찾지 못함(상단 + 버튼과 파일 목록 위 + 버튼이 다름). 해결: 업로드 주소(/upload)로 바로 이동
- 커밋 설명을 비우고 올림. 기본 문구("Add files via upload")로 기록되어 과정 점수용 기록이 약함. 앞으로는 설명을 적기
- 수업 규칙(AI API 금지)을 처음에는 놓치고 AI 기능을 제안했다가 바로잡음
- 이 환경에서는 코드를 실행해 검증하지 못해, 새 버전은 직접 열어 확인하며 고치는 방식으로 진행
